# 基本方針（Policy）

AI WORK OS は、特定の AI モデルに依存しない業務実行の共通基盤である。
業務ルール・品質基準・実行記録を GitHub に置き、実行主体（AI・人間）を交換可能にする。

## 原則

1. **GitHub が正本。** 仕様・タスク契約・判断履歴はこのリポジトリにあるものが正。
   チャット履歴や AI の記憶は正本ではない。
2. **役割は固定しない。** 担当はタスクごとに `assigned_agent` / `reviewer` で指定する（`agents/routing.md`）。
3. **成功条件・失敗条件は実行前に決める。** `ready` になる前に受入基準と失敗条件を確定する。
   結果を見てから基準を変えない。変える場合は新しいタスクとして起票する。
4. **自己申告は合格ではない。** 実装者の「できました」は証拠ではない（`core/quality.md`）。
5. **判断と証拠を分ける。** 実行事実は `evidence`、評価は `quality` に記録する。
6. **再実行・中断・復旧が可能。** 状態はすべてタスク契約に記録し、どのエージェントでも再開できる。
7. **自動修正には上限がある。** `max_retries`（最大3）を超えたら人間にエスカレーションする。
8. **重要判断は人間が行う。** 最終承認（`accepted`）、仕様変更、権限拡大、外部送信は人間が決める。
9. **未確認のことを確認済みと書かない。** 実装していない機能、検証していない項目はそう書く。

## コスト方針

- 個別の LLM API 課金を前提にしない。Claude Code / Codex CLI の既存ログイン環境を使う。
- GitHub Actions への依存は最小限にし、日常の検証はローカル（`scripts/check.sh`）で行う。
- AI 同士の往復は、受入基準で決めたレビュー1往復を基本とし、不要な往復を作らない。

## エスカレーションの条件

次のいずれかで `escalated` にし、`escalation_reason` に理由を書く。

- `failure_conditions` のうち `on_trigger: escalate` のものが発生した
- `retry_count` が `max_retries` に達した
- 受入基準そのものが不適切・矛盾していると判明した
- 権限外の操作（`core/permissions.md`）が必要になった
- 実装者とレビュアーの判定が対立し、証拠で決着しない
