# 品質基準（Quality）

## 3つの品質軸

| 軸 | 問い | 主な検証手段 |
|---|---|---|
| A. `spec_conformance`（仕様適合性） | 求められたものを作ったか | 受入テスト、仕様との照合 |
| B. `correctness`（実装・処理の正確性） | 正しく動くか、結果は正しいか | テスト、機械 diff、再計算 |
| C. `completeness`（成果物の完成度） | 抜け漏れなく仕上がっているか | チェックリスト、レビュー |

3軸は独立に判定し、1つの「OK」にまとめない。

## 判定値

- `PASS` — 証拠があり、判定者が実装者以外
- `FAIL` — 基準を満たさないことが証拠で確認された
- `UNVERIFIED` — 検証していない、または検証手段がない（既定値）

## 原則

1. **証拠がなければ PASS にしない。** 証拠 ID のない `PASS` はスキーマで拒否される。
2. **自己申告は合格ではない。** 実装者自身の `PASS` は無効。判定はレビュアーか人間が行う。
3. **検証不能は未検証。** 検証手段がない項目は `UNVERIFIED` のまま残し、推測で `PASS` にしない。
4. **機械検証を優先する。** コマンドで確認できる基準はコマンドで確認し、終了コードを証拠に残す。
5. **判断と証拠を分ける。** `evidence` には実行事実だけを書き、評価は `quality` に書く。
6. **合格は人間の承認とは別。** `passed` は品質ゲート通過、`accepted` は人間の最終承認。

## 証拠の種類

| `kind` | 内容 | 必須項目 |
|---|---|---|
| `command_output` | 実行したコマンドと結果 | `command`, `exit_code` |
| `file` | 成果物ファイル | `path` 推奨 |
| `diff` | 変更差分 | `path` 推奨 |
| `review_note` | レビュアーの所見 | `summary` 推奨 |
| `log` | 実行ログ（秘密情報を除去済み） | `path` 推奨 |
