### 開発中に見つけて直した欠陥

1. **共有 `.git/config` の競合**（全体実行で発見）: `git checkout -B ... origin/<branch>` が上流追跡設定を共有の
   `.git/config` に書き込み、同時に動くワーカー同士がロックで衝突していた。負けたワーカーはエラーになって再試行し、
   20 タスク試験で同じ段階の取得が 2 回起きた。`--no-track` に変更し、worktree の作成を controller が起動前に順番に
   行うよう変更し、ロック由来の git 失敗を再試行するようにした。修正後は 20 タスク試験を 6 回実行し、すべて成功。
2. **死んだワーカーの worktree がブランチを掴んだまま**（ミューテーション確認で発見）: SIGKILL されたワーカーの
   worktree にタスクブランチが残り、代替ワーカーの checkout が失敗して 60 秒遅れていた。回収前にその worktree を
   解放するよう変更した。

### ミューテーション確認（手動、その後元に戻した）

| 無効化した部分 | 失敗したテスト |
|---|---|
| モデル枠の上限 | `test_model_slots_are_a_hard_limit` |
| 取得トランザクションを `BEGIN IMMEDIATE` から通常の `BEGIN` へ（＋状態ガード削除） | `test_ten_processes_never_claim_the_same_task`（database is locked、3 回中 3 回） |
| 孤児プロセスの停止 | `test_killed_worker_is_replaced_and_its_task_finishes_once`（worker 実行が 2 件） |
| 死んだワーカーの worktree の解放 | 同上（worker error による遅延を検出） |
| ワーカーの親プロセス消失の検出 | `test_controller_killed_then_restarted_resumes` |

状態ガード（`state='queued'`）だけを外したミューテーションは検出されない。`BEGIN IMMEDIATE` だけで排他が成立しており、
状態ガードは二重の防御のため。
